# T073 Handoff — one GUI session script, and a fixtures folder

No RFC. Test infrastructure, required by the owner's GUI test rules
(`.git-exclude/rules/project-instructions-gui-common.md` — a working-copy file,
not in the repository; *Test Optimization Rules*, 2026-11-11): *"Start every
real-UI session with the project's shared session script (isolation, window or
viewport size, capture, teardown). Keep reusable fixtures … in the project's
git-ignored fixtures folder, built or fetched once and recorded with their
checksums, never outside the project."*

## 1. Purpose

**arama has neither.** Every capture task so far (T053, T055, T057 and earlier)
wrote its own launch-and-capture steps, and each one re-derived the isolation,
the window size and the focus check — the places where evidence runs went wrong
before. One script, written and reviewed once, removes that whole class of
error from every later task.

## 2. What the script does

`scripts/gui-session.sh` (committed — the repository is public: **no home-
directory path, no user name, no email address in it**). Bash, like the other
scripts in `scripts/`. Subcommands, or one script with phases — your design,
justified:

1. **Preflight — refuse to start unless all hold:**
   - zero running `arama` instances (exact process name);
   - no `.arama-local/` or `.arama-cache/` beside the binary under test — those
     legacy folders are resolved relative to the **executable**
     (`env/src/dir.rs`: `legacy_local_dir`, `legacy_cache_dir`) and read for
     migration, so a stale one leaks into the run;
   - the backend requested (Wayland or X11) is available.
2. **Isolation:** a fresh scratch directory under `.git-exclude/tmp/`, and
   **every** directory arama reads pointed into it:
   - `ARAMA_DATA_HOME` (settings, models, cache — RFC 041);
   - `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME` (the
     toolkit and the file chooser read and write them: recently-used files are
     state).
   Optionally pre-seed it from a fixture (§3): a `settings.json` pinning theme
   and locale, a model directory, a gallery folder.
3. **Launch at a fixed window size, obtained at launch.** arama has no window-
   size setting, so the rules' other route applies: **a nested compositor sized
   for the purpose.** Default 1280 × 720; a size argument for others. **Never
   resize a running window.** State in the package which nested compositor you
   chose and why; if none works here, stop and report — do not fall back to
   resizing.
4. **Find the window by the instance's pid,** never "the first window", and
   print its id. For an XWayland window, select by X11 class with zero such
   windows before the launch and exactly one after (the rules explain why).
5. **Capture:** a function that takes a name and writes
   `niri msg action screenshot-window --id <id> --path <absolute path>` into the
   session's evidence folder — absolute path, never `import`.
6. **Focus check:** a function every keystroke helper calls first — compares
   niri's focused window with the instance (pid, or id for XWayland).
7. **Record:** a `session.txt` beside the captures: backend, window size, the
   isolation paths (as paths relative to the project root), theme, locale, the
   binary's version and commit.
8. **Teardown:** kill the instance by exact name, confirm zero instances, keep
   the evidence folder, remove the scratch profile unless asked to keep it.

**It does not drive the app.** Clicks, AT-SPI actions and key sequences stay in
each task's own script, which sources this one.

## 3. The fixtures folder

`.git-exclude/fixtures/` (inside the project, git-ignored with the rest of
`.git-exclude/`), with a `README.md` listing each fixture, how it is built or
fetched, and a `SHA256SUMS` file the script verifies before use.

**The first fixtures — only what an open task needs:**

- **A gallery folder:** synthetic images generated by a committed script —
  `scripts/make-gallery-fixture.sh` or similar — **never personal photographs**.
  Enough variety for the gallery and the Similar Pairs dialog to show results:
  near-duplicates and distinct images. Record the generator's version.
- **The models:** a copy of the two models, fetched once with their pinned
  SHA-256s (the same digests as `crates/ai/src/model/model_container/clip.rs`
  and `crates/ai/src/model/model_container/wav2vec2.rs`). A session pre-seeds
  `ARAMA_DATA_HOME` from it instead of downloading ~940 MB per run. The real
  download stays the once-per-release expensive pass.
- **The previous release's build** (for upgrade checks): `arama` 0.42.0 from the
  GitHub Release, with its published checksum. **Fetch only; do not run it as
  part of this task.**

## 4. Change scope

- `scripts/gui-session.sh` (new)
- `scripts/make-gallery-fixture.sh` or equivalent (new)
- `.git-exclude/fixtures/README.md` and `.git-exclude/fixtures/SHA256SUMS`
  (working copy, not in the repository)
- `docs/src/dev/testing.md` — §6

## 5. Non-change scope

- arama's own source. **No window-size setting, environment variable or test
  hook is added to the application** for this.
- Existing tasks' evidence. Do not retake anything.
- CI. The script is for real-UI sessions on a developer's machine.

## 6. Documentation updates

`docs/src/dev/testing.md`: a short section — *"Real-UI sessions"* — saying the
script exists, what it guarantees (preflight, isolation, fixed size, pid-based
window, focus check, record, teardown), and where the fixtures live. Point at
the rules by name; the rules file itself is not public.

## 7. Required tests

- `shellcheck` clean on both scripts (if `shellcheck` is not installed, say so).
- **Each preflight refusal shown failing:** run the script once with an
  `arama` instance already running, and once with a planted `.arama-cache/`
  beside the binary — both must refuse, with a message naming the reason.
- **One end-to-end session:** launch, capture one image at 1280 × 720, teardown.
  Show `session.txt`, and show by machine (the image's pixel size, read with a
  tool, converted from physical to logical px at the display scale) that the
  window was the size asked for.
- **Isolation shown, not assumed:** after the session, the maintainer's real
  arama settings file and the real XDG folders are unchanged — compare their
  modification times (or checksums) before and after.
- `SHA256SUMS` verified by the script.

## 8. Acceptance criteria

- Both scripts committed, `shellcheck` clean, no personal path in them.
- Both preflight refusals demonstrated.
- One end-to-end session, with `session.txt` and the size check.
- Real settings and XDG folders untouched, shown.
- The three fixtures present, each with a checksum, the README describing how
  each is rebuilt.
- `docs/src/dev/testing.md` updated.

## 9. Prohibited shortcuts

- Resizing or floating a running window to get the size.
- Selecting the window by title or "the first one found".
- Using real photographs, or anything from the maintainer's own folders, as a
  fixture.
- A fixture outside the project directory, or one without a checksum.
- Adding anything to arama's source to make testing easier (§5).

## 10. Module boundaries

`scripts/` and `.git-exclude/fixtures/` only, plus one docs page.

## 11. Compatibility constraints

The script runs on this project's Linux/niri development setup. Other platforms
are out of scope; say so in its header.

## 12. Security constraints

- **Privacy:** the repository is public. The committed scripts and docs carry no
  home-directory path, user name, email address or machine name. `session.txt`
  records paths relative to the project root.
- The model fixture is verified against the pinned SHA-256s before use, so a
  corrupted or substituted copy is refused.
- The previous-release binary is checked against its published checksum and is
  not executed by this task.

## 13. Known risks

- **No nested compositor may work on this machine.** Then stop and report, with
  what you tried. The rules forbid the fallback.
- **The display scale:** captures are in physical pixels. The size check must
  convert, and must read the scale from the system, not assume it.
- **Large fixtures** (~940 MB of models, a release archive): fetch once; never
  re-fetch inside a session.
